# Task 1-00: Internationalization (i18n)

**Phase:** 1 — Core
**Priority:** P0
**Dependencies:** Phase 0 scaffold
**Reference:** `documentation/ROADMAP-web-b2c.md` (Section 1.9)

---

## Objective

Set up full internationalization support for the Web B2C application using `next-intl`, with Polish as the default locale and English as the secondary locale. This task establishes the i18n foundation that all subsequent UI tasks depend on — every user-facing string must be keyed through the translation system from the start.

> Note: Canonical URLs and `hreflang` tags in task 1-07 (SEO Foundations) depend on the locale setup from this task (see ROADMAP §1.3.1).

## Deliverables

### 1. i18n Setup

- [ ] P0 Set up i18n in Next.js (`next-intl`) with PL as default locale
- [ ] P0 PL translation file for all web UI strings
- [ ] P0 SSR locale handling — serve PL content, set `<html lang="pl">`
- [ ] P0 EN translation file
- [ ] P0 URL-based locale prefix (`/en/poznan/music` vs `/poznan/music`) for SEO in both languages
- [ ] P0 `hreflang` tags for EN/PL alternate pages

## Design Reference

> Prototype: `documentation/designs/web-b2c/EventB2CWeb/`

- **AppHeader** (`src/components.jsx`) — contains the PL/EN language toggle
- **SearchDiscoveryScreen** (`src/screens.jsx`) — shows toggle placement in header

## Acceptance Criteria

- `next-intl` is installed and configured with PL as the default locale
- PL and EN translation files exist and cover all UI strings present at the time of this task
- SSR-rendered pages include `<html lang="pl">` (or `lang="en"` for English routes)
- Navigating to `/en/poznan` serves English content; `/poznan` serves Polish content
- `<link rel="alternate" hreflang="pl">` and `<link rel="alternate" hreflang="en">` tags are present on every page
- All translation keys resolve without warnings in both locales
- `pnpm type-check` passes with no errors related to i18n
